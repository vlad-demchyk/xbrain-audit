# XAnalyze

Знаходить текст, написаний моделлю, невидимі символи і дефекти доступності, SEO,
швидкодії та безпеки на сайті, в HTML-файлі або в репозиторії - і називає точний
рядок, а не оцінку.

[English](README.md) | [Italiano](README_it.md)

## Для чого це

Вам дали сторінку, тему, веб-парт або репозиторій, і треба відповісти на три
питання: чи цей текст написала модель, чи є в розмітці символи, яких не дає
жодна клавіатура, і чи ця річ доступна й коректна. XAnalyze відповідає на всі
три за один прогін і називає файл і рядок за кожною відповіддю.

Зокрема **сайт SharePoint Online за входом Microsoft 365**: ви входите самі,
прогін читає кожну сторінку сайту з його власного дерева сторінок, і
аудитується лише те, що зроблено для сайту - власні веб-парти й текст авторів,
а не обвʼязка Microsoft. Див. [SharePoint Online](#sharepoint-online).

Це один бінарник із трьома поверхнями - вікно, термінальний інтерфейс і
командний рядок - над одним ядром, тож вони не можуть розійтись у тому, що саме
було виміряно.

## Встановлення

**Застосунок для macOS**

```bash
curl -L -o XAnalyze.app.zip https://github.com/vlad-demchyk/xAnalyze-/releases/latest/download/XAnalyze.app.zip
ditto -x -k XAnalyze.app.zip /Applications/
```

При першому запуску застосунок один раз пропонує покласти себе як `xanalyze` у
`~/.local/bin`, тож CLI і TUI не потребують другого завантаження, а
`xanalyze update` оновлює все три разом. Бандл ще не
підписаний: перший запуск - Control-click -> Open.

**Лише командний рядок**

Завантаження одне, застосунок: вікно, CLI і TUI - одна програма. Щоб отримати
команду `xanalyze`, не відкриваючи вікна:

```bash
/Applications/XAnalyze.app/Contents/MacOS/XAnalyze --install-cli
```

**З вихідників**

```bash
git clone https://github.com/vlad-demchyk/xAnalyze-.git && cd xAnalyze-
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python main.py                                  # вікно
python cli.py fullscan https://example.com      # командний рядок
python cli.py                                   # термінальний інтерфейс
```

**Windows 10/11, з вихідників**

Готового завантаження для Windows поки немає, запуск із чекауту. Потрібен
Python 3.13 або новіший з python.org (лаунчер `py` іде з ним), у PowerShell:

```powershell
git clone https://github.com/vlad-demchyk/xAnalyze-.git; cd xAnalyze-
py -3.13 -m venv venv
venv\Scripts\pip install -r requirements.txt
venv\Scripts\python main.py                              # вікно
venv\Scripts\python cli.py fullscan https://example.com  # командний рядок
venv\Scripts\python cli.py                               # термінальний інтерфейс
```

Вивід завжди в UTF-8, хоч яка кодова сторінка консолі, тож його можна
перенаправити у файл чи передати агенту. Налаштування, резервний файл
облікових даних і сесії сайтів із входом лежать у `%APPDATA%\xanalyze`,
власний лог застосунку в `%LOCALAPPDATA%\xanalyze\logs`, ключі йдуть у
Windows Credential Manager. `xanalyze update` оновлює лише застосунок для
macOS; на Windows чекаут оновлюється через `git pull`.

Збірка для Windows (`dist\XAnalyze\XAnalyze.exe` для вікна і
`xanalyze-cli.exe` для командного рядка і TUI): `pip install pyinstaller`,
потім `powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1`.

## Як користуватись

```bash
xanalyze                                      # термінальний інтерфейс
xanalyze fullscan https://example.com         # усе за один прогін
xanalyze fullscan ./my-project                # те саме по репозиторію
xanalyze scan ./src                           # лише AI-патерни і символи
xanalyze audit ./page.html                    # лише правила сайту
xanalyze fix ./src                            # виправити символи (лишає .bak)
xanalyze runs                                 # список, продовження, порівняння
```

`fullscan` - це відповідь на «перевір оце». URL обходиться і рендериться; тека
читається як вихідний код, якщо `--devserver` не запустить власний сервер
проєкту; один HTML-файл читається як завершена сторінка, якою він і є.

### Команди

| Команда | Що робить |
|---|---|
| `fullscan ЦІЛЬ` | AI-патерни, символи і всі правила сайту, плюс звіти |
| `scan ШЛЯХИ` | AI-патерни і неклавіатурні символи, нічого не змінюючи |
| `audit ЦІЛЬ` | лише правила сайту: URL, HTML-файл або тека |
| `fix` / `undo` | застосувати точні виправлення символів; повернути копії `.bak` |
| `runs` / `resume` / `compare` | прогін є обʼєктом: перелічити, продовжити, звірити з попереднім |
| `ignore FINGERPRINT --reason TEXT` | позначити одну знахідку як хибну в `.xanalyze-ignore` разом із причиною; відбиток є в `audit --json`, а кожен наступний прогін каже, скільки приховано і чому |
| `login URL` | увійти на сайт власноруч, у справжньому браузері, щоб прогін бачив те, що за дверима; зберігається лише після «Готово» |
| `logs` | що прогін насправді робив, у форматі JSON Lines |
| `ai` | акаунт для проходів із моделлю: `status`, `login`, `rewrite` |
| `agent-scan` / `agent-judge` | віддати кандидатів агенту і прийняти його вердикти |
| `clean` | фільтрує текст зі stdin у stdout |
| `update` / `uninstall` | самооновлення з останнього релізу; повне видалення |

Оновлювач готує й перевіряє GUI-бандл до заміни та відновлює попередній застосунок,
якщо встановлення не вдалося. Часткове оновлення CLI/GUI повертає код `3` і називає
компонент із помилкою; перед повторною спробою в TUI знову перевір оновлення.

Нові записи логів приховують облікові дані URL, параметри запиту, фрагменти й поля
секретів. На macOS/Linux логи та резервний файл ключів доступні лише власнику;
оновлення файлу ключів атомарні й узгоджені між процесами.

Інкрементальний скан звіряє прочитаний текст, параметри, виключення знахідок і версію
застосунку. AI-висновки використовують окремий кеш суджень. Одночасні записи кешів
сканування, браузера й суджень зливають зміни під блокуванням та атомарно замінюють файл.

`xanalyze КОМАНДА --help` друкує всі параметри. Ті, які варто знати:

| Параметр | Навіщо |
|---|---|
| `--depth N`, `--max-pages N` | як далеко йде обхід і скільки сторінок; сторінка понад 10 МБ позначається як непрочитана, а зображення з приватних і локальних адрес, яких обхід сам не відвідував, не завантажуються |
| `--repo ШЛЯХ` | репозиторій за сайтом, щоб знахідка називала файл, а не лише сторінку |
| `--devserver` | запустити власний dev-сервер проєкту і аудитувати відрендерене |
| `--breakpoints all` | аудит на всіх ширинах; без нього одна (1440x900) |
| `--color-scheme dark` | показати сторінці `prefers-color-scheme: dark`, щоб перевірити темну тему; одна схема на прогін |
| `--no-browser` | лише статичне читання, і значно швидше |
| `--detector НАЗВА` | `offline` (типово, безкоштовно), `embedding`, `hybrid`, `ai` |
| `--category`, `--confidence` | звузити показане; обидва є видом на один прохід |
| `--within СЕЛЕКТОР` | аудит лише цієї частини сторінки - відданого віджета чи веб-парта |
| `--report ШЛЯХ`, `--styled-report ШЛЯХ` | брифінг для агента (`.md`/`.json`) і звіт для людини (`.pdf`/`.html`) |
| `--json`, `--check` | машинний вивід; код виходу 1 за серйозних знахідок |
| `--progress jsonl` | одна JSON-подія на рядок у stderr, **поки** прогін іде |
| `--language uk\|it\|en` | мова звіту; інакше визначається за сторінками |
| `--project НАЗВА` | один проєкт із теки, де їх кілька: за назвою теки або за шляхом |
| `--start-command КОМАНДА`, `--dev-server-port N` | що запускати замість знайденого скрипта і який порт очікувати |
| `--no-session` | читати сайт так, як його бачить стороння людина, ігноруючи збережений вхід |
| `--profile-defaults` | увімкнути те, що просить розпізнаний стек (див. нижче) |

## Що саме перевіряється

**Текст, написаний моделлю.** Офлайновий прохід читає ритм речень, повторювану
структуру і кліше і називає фразу, яку зіставив, тож із знахідкою можна
сперечатись. Для другої думки є прохід на embedding і прохід із моделлю. Це не
доказ авторства.

**Неклавіатурні символи.** Нульової ширини, гомогліфи, незвичні пробіли,
стилізовані літери і типографські символи - кожен точний і кожен виправляється
на місці.

**Правила сайту** за категоріями, з кількістю, яку стежить набір тестів:

`accessibility` (40), `best-practices` (13), `geo` (2), `performance` (8), `security` (10), `seo` (8)

Правило працює там, де має сенс, і ніде більше, і вирішує це доказ: синтаксис
файла (правила JSX лише в `.jsx`/`.tsx`), призначення документа (правила листа
лише на листі) і стек, який проєкт довів на диску (правило екранування
WordPress лише у WordPress). У файлі React правила читають компонент так, як
його написано: два елементи в різних гілках умови, `cond &&` / `!cond &&` чи
в окремих `return` не є дублікатом id, текст у коді (`JSON.parse`,
`CSS.escape`) не є текстом, компонент дизайн-системи з пропом `label` має
назву, а селектори показують шлях JSX (`section.card > div.list > img`). Літеральний `aria-label`,
`placeholder`, `title` чи `alt` у файлі, який решту текстів перекладає,
позначається як `advisory` (`jsx-untranslated-literal`).

**Написано під те, що знайшов ручний аудит.** `alt` у формі слага
(`mappa-parlante-example`, `Piazza-Grande`, дата), а не лише імʼя файла з
розширенням; вбудоване відео YouTube, Vimeo чи подібне, про субтитри,
транскрипт і аудіоопис якого сторінка нічого не каже (1.2.2, 1.2.3, 1.2.5);
кнопка «завантажити ще» на сторінці без live region (4.1.3); а на обійденому
багатомовному сайті - посилання, яке в перекладі веде не туди, куди в
оригіналі (2.4.4). Перевірки відео, live region і посилань у перекладах мають
певність `advisory`: вони кажуть, куди має подивитись людина, а не що сторінка
провалена. Посилання, які в перекладі стоять в іншому порядку, зіставляються за
словами і ціллю, а не за позицією. Адреси пошуку й фільтрів, чий canonical не
вказує на них самих, не перевіряються на взаємний hreflang і рахуються одним
рядком. Посилання, яке HTML_CodeSniffer називає картинкою без `alt`, але яке має
назву з `aria-label`, `aria-labelledby` чи `title`, - це нагадування перевірити
назву, а не порушення.

**У браузері**, коли він доступний: axe-core і HTML_CodeSniffer, сторінка в
тому стані, у який її приводить людина - індикатор фокуса і чи видно його на
тлі (3:1), чи липка шапка не закриває елемент у фокусі (2.4.11), клавіатурні
пастки, порядок фокуса, вміст лише під наведенням, відкрите модальне вікно,
подорож формою, розмір кожної цілі для натискання і вільне місце навколо неї
(2.5.8, вимірює axe-core, у знахідці розмір і найближча ціль) - і та сама
сторінка на кількох ширинах. Він читає і ніколи не
діє: нічого не вводиться, не натискається і не відправляється. У десктопному
застосунку прихована сторінка не може взяти фокус вікна, не віднявши його в
головного вікна, тому три перевірки фокуса там повідомляють
`focus-not-measured` (видно з `--unsettled`); командний рядок їх вимірює. Кожна
знахідка несе критерії WCAG, до яких вона належить, у звіті та в `--json`
(`wcag`).

**Походження, а не вирок.** Поля IPTC/XMP і маніфести C2PA у кожному
зображенні, на яке посилається сторінка (завантажуються лише перші 512 КБ), і
факти репозиторія: `.env` під контролем версій, коміти з іменем асистента,
закомічена конфігурація асистента. Це подається як факт про походження, ніколи
як дефект.

**Певність.** Кожна знахідка є `exact`, `needs-browser` або `advisory`.
Невирішене типово не показується - на одній справжній сторінці це було 312 із
348 знахідок контрасту - і прогін каже, скільки лишив поза списком.
`--unsettled` їх повертає, `--confidence exact` прибирає ще й дорадчі.

**Унікальні проблеми, а не повтори.** Заголовок підсумку, `counts` у `--json`,
рядок стану вікна і терміналу рахують кожну проблему один раз: шапка чи
SVG-спрайт є на кожній сторінці, тож обхід 381 сторінки давав 15 338 знахідок
і близько 980 причин. Входження лишаються поруч (`occurrences`, `distinct` і
`problems` у `--json`, кожна із сторінками), а кожна знахідка все одно в списку.
Підказки HTML_CodeSniffer «перевірте вручну» (назва й видимий текст,
`position: fixed`, ігноровані зображення, «використайте список») і скасований
WCAG 4.1.1 мають `advisory` та `minor`; те, що рушій виміряв, наприклад
співвідношення контрасту, зберігає свою вагу.

**Сервер локального сайту не є дефектом проєкту.** На `localhost`, `*.local`,
`*.test` чи приватній адресі те, що вирішує сервер і що неминуче при звичайному
HTTP, не потрапляє до списку, а лише рахується: відсутні заголовки
`Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`,
`X-Frame-Options`, стиснення й кешу, `http://` в `action` форм і `noindex`
розробницької копії. Один обхід локального WordPress мав 365 критичних
знахідок, які всі були формами з `http://`. Прогін каже, скільки лишив поза
списком (`environment` у `--json`); `--include-environment` їх показує. Усе, що
стосується самої сторінки (синхронний сторонній скрипт, зображення, доступне
імʼя), на локальній адресі звітується так само, як на публічній, а аудит
репозиторію не змінюється.

## Ціль вирішує, що питати

Проєкт оголошує, чим він є, і з цього випливає більше, ніж список тек, які
треба пропустити. Рішення SPFx знає, що віддає веб-парти, і не знає, на який
сайт вони стануть. Застосунок на Vite чи Next, прочитаний із диска, - це
шаблони, яких збірка ще не виконала, де `<App />` не є заголовком. Один
самодостатній HTML-файл нікуди не веде, тож лишається єдина вісь - ширина.

Кожне з цього стає параметром, і кожен приходить зі стеком, який його попросив,
і з файлом-маркером, що цей стек довів: «увімкнено, бо …» є реченням, з яким
можна не погодитись, а не мовчазним дефолтом. **Те, що ви задали самі, не
перезаписується ніколи.**

Вікно і термінальна форма це застосовують: контрол увімкнено, причина під ним,
знімається одним кліком. Командний рядок - ні: він є контрактом, і прогін, що
запустив dev-сервер, бо знайшов `vite.config.ts`, був би не тим прогоном, який
написав автор скрипта. Там ті самі пропозиції друкуються рядками `# [profile]`
у stderr, а `--profile-defaults` просить їх застосувати.

Те саме читання вирішує, які поля взагалі існують: `--depth` потребує адреси,
`--incremental` - файлів на диску, а контрол, який для цієї цілі нічого не
досягає, не показується і не читається, тож `--devserver`, увімкнений для
репозиторія, не піде за вами на один файл.

Тека з кількома проєктами питає, а не зливає їх мовчки: двадцять рішень SPFx в
одній теці - це двадцять артефактів. `--project НАЗВА` і селектор у вікні та в
термінальній формі аудитують один із них окремо, і скан, файл виключень та
dev-сервер ідуть за ним разом, тож вони не можуть описувати різні проєкти.
Репозиторій, який довів щось про себе, лишається одним проєктом: `web/` у
Bedrock - це докрут того ж проєкту, а не другий проєкт.

**У монорепо dev-серверів кілька, і це різні прогони.** Кореневий скрипт `dev`
запускає або оркеструє застосунки під ним, а в кожного застосунку є власний
скрипт. `--devserver` досі обирав мовчки. Тепер прогін каже, який саме
запуститься і що вказаний проєкт запустить власний - заміряно на справжньому
воркспейсі, де корінь оголошує `workspaces: ["apps/*"]`, а кожен із чотирьох
застосунків - свій `dev`. `--start-command` перевизначає скрипт там, де не
підходить жоден.

## Робота, віддана як фрагмент чужого сайту

**Тема або плагін WordPress** розпізнається так, як їх розпізнає сам WordPress
- за заголовком `Theme Name:` у `style.css` і `Plugin Name:` у головному
PHP-файлі, - а її шаблони читаються як фрагменти, тож ніхто не питає з
`header.php` канонічного посилання чи `<h1>`.

**Веб-парт SharePoint** є однією гілкою сторінки, що належить тенанту.
`--within СЕЛЕКТОР` звужує аудит до неї і вимикає, з друкованою причиною, усе,
що за побудовою читає документ цілком. Згенерований суфікс класу (`root-137`)
не треба вписувати: селектор повторюється за основою. `--repo ШЛЯХ
--web-parts` працює в інший бік - читає маніфести рішення і знаходить частини
цього репозиторію всюди, де вони є на сайті.

Розмітка всередині **шаблонного літерала** теж аудитується. `.ts` і `.js`
пропускаються як файли - `<` у них є оператором, - але рядок у зворотних лапках
не є кодом, а класична веб-частина SPFx будує в ньому весь свій інтерфейс.
Заміряно на справжньому рішенні: 72 із 168 `.ts`-файлів і 131 знахідка, яких не
читав ніхто.

## Сайти за логіном

`xanalyze login https://example.com/admin` відкриває справжній браузер на
власній формі сайту. 2FA, SSO і капча працюють, бо це браузер. XAnalyze ніколи
не бачить ні логіна, ні пароля: зберігається те, що сайт віддав тому браузеру,
окремо на кожен хост і читаним лише для вас. `--no-session` читає сайт так, як
його бачить стороння людина; `login --list` і `login --forget ХОСТ` керують
збереженим. Нічого про сесію не потрапляє ні у звіт, ні в журнал, ні в термінал.

Обхід також фіксує, коли адреса відповіла дверима, а не сторінкою, і каже про
це прямо: чистий підсумок по самих лише формах входу є найоманливішим виводом,
який цей інструмент може дати.

## SharePoint Online

Адреса `*.sharepoint.com` розпізнається ще до читання сторінок, і прогін
змінюється відповідно - однаково в `audit` і `fullscan`, з тими самими
прапорцями, відмовами (код 2) і зонами в JSON - кожна зміна друкується з причиною, а **те, що ви
задали самі, має перевагу**:

- **Спершу вхід.** Без збереженої сесії SharePoint на кожну адресу відповідає
  сторінкою входу Microsoft. `xanalyze login https://contoso.sharepoint.com/sites/ExampleSite`
  відкриває справжнє вікно браузера; завершіть там вхід у Microsoft 365, разом
  з MFA, і натисніть «Готово», коли повернетесь на сайт. Вікно підсвічує
  «Увійти на сайт», термінальна форма друкує цю команду, а CLI відмовляє в
  прогоні й пояснює чому, замість аудиту сторінки входу.
- **Усі сторінки, від самого сайту** (`--page-tree sharepoint`). Сторінки є
  елементами бібліотеки сторінок сайту і читаються через REST API SharePoint
  від вашого імені; обхід посилань знаходить лише те, на що послались.
  `--page-tree links` повертає обхід посилань.
- **Один сайт тенанта** (`--site-scope /sites/ExampleSite`). Один хост
  обслуговує всі сайти; обхід лишається в межах заданого шляху.
- **Рендер сторінок.** Сучасна сторінка збирається в браузері, тож кожна
  рендериться, а ліниві веб-парти прокручуються у видиму зону перед аудитом.
- **Зони.** Панель Microsoft, навігація і панель команд не аудитуються, лише
  рахуються. Власні (SPFx) веб-парти отримують усі правила, кожен екземпляр
  окремо. Текст авторів отримує всі правила; стандартні веб-парти - лише
  правила вмісту (alt-текст, текст посилань, заголовки, ШІ-формулювання).
  Знахідки несуть свою зону у звіті. `--ootb-registry FILE` додає ідентифікатори
  веб-партів Microsoft, зчитані з живої сторінки, щоб незнайомий вбудованому
  списку парт не аудитувався як власний код. Парт, який SharePoint
  розмістив, але не відрендерив, так і показується, а не зливається з
  «знахідок немає».
- **SPFx поза канвасом.** Парт може малювати свою розмітку в обвʼязку
  сторінки (власний хедер, спливне вікно). Її знаходять за класами CSS-модулів
  (`name_1a2b3c4d`), привʼязують до парту з тим самим аліасом або бандлом і
  аудитують як кастом - це висновок, і звіт так його й позначає.

Межі:

- **Conditional Access може відмовити у вході** з некерованої машини чи
  вбудованого браузера. Це політика тенанта, і жодне налаштування тут її не
  обходить.
- **Селектори зон частково є гіпотезами.** Розмітка SharePoint не є публічним
  контрактом; селектори позначені як перевірені або гіпотези в
  `audit/sharepoint_zones.py`, і зміна з боку Microsoft може перенести ділянку
  не в ту зону, доки їх не оновлено.
- **Документи лише перелічуються.** Файли бібліотек (PDF, Office) потрапляють
  тільки в інвентар JSON-підсумку.
- Сесія, яка ввійшла, але не має прав на сайт, так і звітується, і нічого не
  аудитується.

## Звіти

Кожна команда пише теку прогону за датою, типово в `~/Documents/XAnalyze/`
(`XANALYZE_REPORT_ROOT` змінює місце). Архів, що лишився в `~/Desktop/XAnalyze/`
від попередньої версії, переїжджає при першому прогоні: історія прогонів, яка
потрібна для порівняння, лишається там, де інструмент її шукає.

```text
XAnalyze/example.com/2026-09-02-0930/
  report.md     згрупований брифінг для агента
  report.pdf    звіт для людини
  timings.md    час етапів
  changes.md    що змінилось від попереднього прогону
  state.json    стан для продовження
```

Кожен документ починається з того, яка це була команда і які параметри змінили
виміряне. Повторювана проблема перелічена один раз, а її місця вкладені під
нею. `--json` зберігає кожну знахідку - для CI.

Через це групування у зведенні співіснують дві одиниці виміру, тож кожен
його рядок називає свою: категорія рахує **окремі проблеми**, таблиця
символів - **входження**, і обидва числа надруковані під одним заголовком,
а не одне замість іншого. Пʼять проблем типографіки на пʼятдесят два
входження - це два факти, а не суперечність.

## Керування з агента

`--json` відповідає, коли прогін уже завершився. На сайті з тридцяти сторінок
це хвилини мовчання, і той, хто запустив прогін, не відрізнить повільний обхід
від зависання. `--progress jsonl` пише один JSON-обʼєкт на рядок у **stderr**
під час прогону, а stdout лишається таким, як був:

```bash
xanalyze fullscan https://example.com --progress jsonl
```

```json
{"event":"run.start","ts":"…","command":"fullscan","target":"https://example.com","version":"0.63.0"}
{"event":"stage","ts":"…","name":"crawl","state":"begin","depth":1,"max_pages":30}
{"event":"page","ts":"…","n":3,"of":30,"url":"https://example.com/pricing","depth":1}
{"event":"stage","ts":"…","name":"crawl","state":"end","pages":12}
{"event":"notice","ts":"…","kind":"authwall","text":"2 address(es) answered with a login wall …"}
{"event":"run.end","ts":"…","exit_code":0,"counts":{…},"documents":31,"sources":12}
```

| `event` | Коли | Поля |
|---|---|---|
| `run.start` | перший рядок | `command`, `target`, `version` |
| `stage` | етап починається, звітує про хід або закінчується | `name` (`devserver`, `scan`, `crawl`, `audit`, `browser`, `report`), `state` (`begin`, `progress`, `end`) |
| `page` | кожна прочитана сторінка | `n`, `of`, `url`, `depth` |
| `file` | кожен відкритий файл | `n`, `of`, `path` |
| `notice` | усе, що термінал сказав би прозою | `kind`, `text` і поля події |
| `finding` | одна на знахідку, з `--progress jsonl=findings` | `rule`, `severity`, `source`, `line`, `kind` |
| `run.end` | останній рядок | `exit_code`, `counts`, `documents`, `sources` |

Без прапорця не змінюється нічого: ті самі людські рядки, жодного JSON.
`finding` вимкнена, доки її не попросять, бо на великому сайті таких подій
десятки тисяч.

Це не дефолт, і свідомо: людина за терміналом хоче речень, а прогрес і так
увімкнений - `jsonl` міняє **формат**, а не те, чи прогін про себе звітує. Хто
саме читає - властивість середовища, а не команди, тож постав
`XANALYZE_PROGRESS=jsonl` один раз, і кожен прогін у тій оболонці говорить
ним; `--progress human` на окремій команді все одно перемагає, тож будь-який
один прогін можна прочитати очима. Рядок, який не парситься як JSON, XAnalyze не писав - Qt пише
власну діагностику в той самий потік, - тож його треба пропустити, а не
падати на ньому.

**Коди виходу** однакові для всіх команд:

| Код | Значення |
|---|---|
| `0` | чисто - команда відпрацювала і не має про що звітувати |
| `1` | є знахідки, і лише з `--check`. `scan`/`fix`/`clean`: будь-яка знахідка. `audit`/`fullscan`: критична або серйозна |
| `2` | помилка - команда не могла виконатись: шлях не існує, прапорець не застосовний, детектор не зміг прочитати текст |
| `3` | незавершено - прогін спинився на пів дорозі, його робота на диску; `xanalyze resume` продовжує |

## Інтерфейси

**Вікно** (`python main.py` або застосунок). Екран налаштування цілі й прогону,
далі список знахідок поруч із превʼю вихідного коду або відрендереної сторінки,
з виправленнями, оглядом замін і експортом звіту. Дві ширини можна вивести
одночасно, щоб закрити питання «це ламається лише на мобільному».

**Термінал** (`xanalyze` без аргументів). Scan, Audit, Full Scan, Reports,
Settings, Account, Update, Logs. Стрілки, цифрові скорочення, `Tab`, `Esc` і
`Ctrl+R` для запуску.

Механічні виправлення позначено типово; чернетки моделі завжди потребують
перегляду; рішення на кшталт альтернативного тексту до фотографії ніколи не
подаються як автоматичне виправлення.

## Конфігурація

Налаштування живуть у `~/.config/xanalyze/settings.json` (на Windows
`%APPDATA%\xanalyze\settings.json`) - мова, провайдер, `max_pages`, категорії символів.

`.xanalyze-ignore` у корені проєкту використовує синтаксис gitignore і вміє
глушити за правилом, селектором або відбитком:

```text
vendor/
*.min.js

[rules]
meta-viewport

[fingerprints]
083bea550659aadb  # текст логотипа вже є в посиланні
```

Відхилити знахідку з причиною можна однією командою: `xanalyze ignore
FINGERPRINT --reason "…"`, відбиток береться з `audit --json`. Кожен наступний
прогін каже, скільки знахідок приховано, і наводить причини, тож прихована
знахідка ніколи не виглядає як чиста сторінка.

## Як правила аудиту тримаються чесними

- **Корпус перевірених вердиктів.** `corpus/audit/verdicts.jsonl` містить
  справжні дефекти й відомі хибні спрацювання з джерелом кожного. Кожне
  правило рівня serious чи critical має хоча б по одному прикладу обох типів,
  і тести падають, щойно правило пропускає перше або повідомляє друге.
- **Точність на ваших аудитах.** `python -m audit.precision AUDIT.json
  --template labels.jsonl` дає список знахідок, які треба позначити як вірні чи
  хибні; `--labels labels.jsonl` друкує точність кожного правила з кількістю
  позначених поруч, а менше п'яти називає «not measured».
- **Оновлення рушіїв перевіряються, а не приймаються на віру.** Після
  оновлення axe чи HTML_CodeSniffer код, якого не було в перевіреній версії,
  показується як примітка, доки хтось його не перегляне
  (`python -m audit.engine_codes`).

## Шаблони, які він розуміє

Чотирнадцять шаблонних мов мають **пару** фікстур у
`tests/fixtures/frameworks`: той самий компонент, написаний так, як велить його
фреймворк, і написаний неправильно. Правильна половина не має давати знахідок,
а зламана - має давати саме потрібні, тож це заміряне твердження:

`alpine`, `angular`, `blade`, `django`, `erb`, `handlebars`, `liquid`, `php`, `razor`, `react`, `svelte`, `thymeleaf`, `twig`, `vue`

Розмітку поза цим списком він усе одно читає - парсер її не відкидає, - але
ніщо не довело, що коректний файл у ній повертається чистим.

**Серверний шаблон читають обидва проходи.** В'ю `.blade.php`, `.php` теми
WordPress, файл `.twig`, `.erb`, `.ejs`, `.phtml` чи `.liquid` - це розмітка з
домішаною серверною мовою, тож його копію читають проходи AI-патернів і
символів так само, як читали б `.html`, який він віддає, а його розмітку
аудитують так само. Те, що видає шаблонна мова - `{{ $plan->name }}`,
`<?php echo … ?>`, `@endsection`, - копією не є і як копія не читається. Файл
`.php`, який є контролером, а не в'ю, лишається кодом: `$id < 10` - це
порівняння, а не тег.

## Стеки, які він розпізнає

Проєкт визначається за власними файлами-маркерами, і те, чим він виявився,
вирішує, що вважати чужим кодом, а не написаним тут:

`angular`, `astro`, `bedrock`, `beehiiv`, `carrd`, `craft`, `django`, `docusaurus`, `dotnet`, `drupal`, `eleventy`, `ember`, `flutter`, `gatsby`, `ghost`, `hugo`, `jekyll`, `joomla`, `laravel`, `magento`, `nextjs`, `nuxt`, `qwik`, `rails`, `remix`, `sharepoint`, `shopify`, `silverstripe`, `spfx`, `spring`, `squarespace`, `statamic`, `storybook`, `sveltekit`, `symfony`, `typo3`, `vite`, `wagtail`, `webflow`, `wix`, `wordpress`, `wordpress-plugin`, `wordpress-theme`

Розпізнавання є доказом: профіль називає файл, який його довів, виключення
проголошуються, а не застосовуються мовчки, і одним кліком їх можна скасувати.

## Межі

- Виявлення AI-тексту залежить від корпусу. Це не доказ авторства, а судження
  моделі не є детермінованими.
- **Виявлення тексту охоплює лише українську, італійську й англійську.**
  Пасаж іншою мовою так і називається і лишається без оцінки, замість міряння
  списками, які цієї мови не знають. Перевірки символів і сайту не залежать
  від мови.
- **Офлайновий прохід слабкий італійською**: на відкладеній половині корпусу
  він знаходить 36 % відомих AI-пасажів проти 55 % англійською і 71 %
  українською, тоді як embedding знаходить 100 %, 85 % і 86 %. Прогін по
  італійських сторінках каже про це і називає кращий детектор.
- Скан теки не бачить вмісту, який зʼявляється лише після рендерингу.
  Використовуйте URL або `--devserver`.
- Одна ширина не описує адаптивну поведінку. Використовуйте `--breakpoints all`.
- Одна колірна схема на прогін: сайт із темною темою потребує другого прогону з `--color-scheme dark`.
- Типографські перевірки можуть позначити навмисну пунктуацію
  (`--no-typography`).
- Читання C2PA потребує необовʼязкових `c2pa-python` і `cryptography`.

## Збірка релізу

```bash
make version        # що каже config.py
make rebuild        # один бандл: вікно, CLI і TUI на цій версії
make package        # XAnalyze.app.zip і маніфест, те, що шукає `xanalyze update`
```

`make package` відмовляється працювати над застарілим бандлом. Архів поки не
підписаний і не нотаризований.
